Ты Senior Full-Stack Developer. Продолжи разработку платформы **MediFinder** (Кыргызстан, интерфейс на русском, валюта сом, Next.js 14 + TypeScript + Tailwind + Framer Motion + Lucide, деплой на Vercel). Полное ТЗ приложено отдельным файлом и остаётся главным источником требований. Прочитай код, не переписывай рабочее.

## Что уже сделано и ПРОВЕРЕНО (npm install, tsc --noEmit, next build проходят; сценарии прогнаны Playwright)

- **Local** (покупатель, аптека): каталог, поиск с опечатками, корзина с делением по филиалам, заказы с резервом 24 ч, кабинет покупателя и аптеки. Сценарий покупатель → аптека → покупатель проходит; аптека не видит чужие заказы.
- **Global** (этап 3 выполнен на демо-хранилище): `/global` (заявка покупателя даже на 1 упаковку, чекбокс про рецептурные требования, подтверждение или отказ после проверки), `/supplier` (только обезличенный спрос, без покупателей и комментариев, отправка предложения), `/importer` (одобрить или отклонить предложение, отказ только с причиной). Статусы: new, offered, importer_approved, importer_rejected, buyer_confirmed, buyer_declined, cancelled. Уведомления на каждом шаге. Файлы: `src/lib/global-actions.ts`, `src/components/GlobalForms.tsx`, `src/app/{global,supplier,importer}/page.tsx`. Данные хранятся в таблице `kv` SQLite как JSON (на Supabase заменить на таблицы `international_request`, `supplier_offer`, `import_verification`, `buyer_confirmation`).
- Роли supplier и importer входят через демо-вход и попадают в свои кабинеты. Проверена защита маршрутов (аптека не открывает `/supplier`).
- `supabase/migrations/0002_rls_and_functions.sql`: RLS-политики по ролям, обезличенное представление `supplier_demand`, атомарные функции `place_retail_order`, `confirm_retail_order`, `release_retail_order`, `expire_reservations`, `write_audit`. **Проверен только синтаксис (pglast), на живой БД Supabase НЕ запускался.** Нужно применить на тестовом проекте и проверить политики реальными пользователями каждой роли.
- Next обновлён до 14.2.35 (закрыта уязвимость версии 14.2.18).

## Известные ограничения

- SQLite (`node:sqlite`) не работает на Vercel (временная файловая система). Демо-вход по cookie без пароля небезопасен и должен быть заменён.
- Карты нет, только схематичный SVG. Админ-кабинет, Group Orders, Cargo не реализованы (`/coming-soon?role=admin`).
- Supabase не подключён: пакет `@supabase/supabase-js` не установлен, `store.ts` и `actions.ts` всё ещё на SQLite.
- Перед тестом после правок кода удаляй `./data` и перезапускай dev-сервер (состояние кэшируется в `globalThis`).

## План работ (по порядку, после каждого шага запускай `npx tsc --noEmit`, `npx next build` и сценарий)

1. **Supabase:** применить `0001` и `0002` на тестовом проекте; сид-данные из `src/lib/seed.ts`; Supabase Auth вместо cookie-входа (роль в `user_profile`, аптека привязана через `organization_id`); переписать `store.ts`, `actions.ts`, `global-actions.ts` на `@supabase/supabase-js` (серверный клиент с service role только на сервере; пользовательские операции через RPC из `0002`); запись в `audit_log` и историю статусов; создание первого администратора скриптом; cron для `expire_reservations()`. Ключи только в `.env` и Vercel.
2. **Group Orders:** объединение только при совпадении препарата, дозировки и формы; общий спрос; предложения на объёмы; отдельное подтверждение каждым покупателем; продление или закрытие группы. Следуй паттерну Global (серверные действия с zod и requireRole, формы-клиенты, обезличенность для поставщика).
3. **Cargo:** отправки с разными препаратами, заказ даже на 1 упаковку, проверка совместимости и условий хранения (логистические группы по `storage_class`), прозрачный расчёт стоимости (демо-значения помечать), статусы из ТЗ, распределение по городам и точкам выдачи, альтернативная точка только с согласия покупателя, у каждого покупателя своя запись внутри общей отправки.
4. **Кабинеты:** администратор (пользователи, аптеки, каталог, заказы, проверки, управление демо-данными), расширить поставщика и импортёра, аналитика без персональных данных.
5. **Финал:** мобильная и планшетная проверка, пустые состояния, ошибки и загрузка у всех списков, защита от двойной отправки форм, `.env.example`, README, инструкция деплоя на Vercel.

## Правила

- Никаких эмодзи вместо иконок (только Lucide), никаких фиктивных кнопок и TODO вместо обязательных функций.
- Все демо-данные помечены как тестовые; не выдумывать реальные аптеки, лицензии, партнёрства, отзывы.
- MediFinder — посредник: не продаёт, не хранит и не импортирует лекарства, не обещает ввоз до проверки импортёром, не обходит рецептурные требования.
- Не заявлять о готовности того, что не запускалось и не проверено. В конце дать список реализованного, изменённых файлов, демо-аккаунтов и инструкцию деплоя.
