# MediFinder (демо: Local + Global)

Платформа поиска лекарств для Кыргызстана. Реализовано: **Local** (каталог, поиск, аптеки, геолокация и выбор города, корзина, заказы с резервом 24 ч, кабинеты покупателя и аптеки, уведомления) и **Global** (индивидуальная заявка на препарат даже на 1 упаковку, предложение поставщика, проверка импортёром, подтверждение покупателем; кабинеты поставщика и импортёра).

**Не реализовано:** Group Orders, Cargo, кабинет администратора, настоящая авторизация, подключение Supabase. Остаются на следующие этапы (см. `CONTINUE_PROMPT.md`).

> Все аптеки, адреса, цены и остатки — **тестовые**. Это не реальные организации. MediFinder — посредник: не продаёт, не хранит и не ввозит лекарства.

## Статус проверки

Выполнено и пройдено: `npm install`, `npx tsc --noEmit`, `npx next build`. Сценарии прогнаны Playwright на dev-сервере: Local (покупатель → аптека → покупатель, изоляция аптек), Global (заявка → предложение → проверка → подтверждение, обезличенность для поставщика, защита маршрутов, отсутствие горизонтальной прокрутки на ширине 390 px). Не проверялось: планшетная ширина, реальный Supabase, деплой на Vercel, миграция `0002` на живой БД (проверен только синтаксис).

## Демо-аккаунты (без пароля)

Страница `/login`: покупатель, две тестовые аптеки (А и Б), поставщик, импортёр, администратор. Рабочие кабинеты: покупатель, аптеки, поставщик, импортёр.

Сценарий Local: войти покупателем → найти лекарство → «В корзину» → «Отправить в аптеки» → выйти и войти аптекой, у которой есть заказ → подтвердить → выдать → вернуться покупателем и проверить статус.

## Хранилище: SQLite

Заказы, остатки и уведомления сохраняются во встроенный SQLite (`node:sqlite`, нужен Node >= 22.13, пакеты не требуются). Файл: `./data/medifinder.db` (меняется через `DATABASE_PATH`). Таблицы создаются автоматически, остатки заполняются тестовыми данными при первом запуске. Чтобы сбросить демо, удалите папку `data/`.

Ограничения:
- Рабочий набор держится в памяти процесса и целиком записывается в файл после каждого изменения. Это нормально для демо, но не для нескольких одновременных инстансов.
- **Vercel не подходит для SQLite**: файловая система временная, файл лежит в `/tmp` одного инстанса и пропадает. Для Vercel нужен Postgres.
- Вход в демо по cookie без пароля не годится для production.

## База данных (план)

Схема: `supabase/migrations/0001_schema.sql` (все сущности из ТЗ) и `0002_rls_and_functions.sql` (RLS и атомарные функции; на живой БД не применялись, проверен только синтаксис). Подключение: создать проект Supabase, выполнить миграцию в SQL Editor, заполнить `.env` по `.env.example`, затем переписать `src/lib/store.ts` и `src/lib/actions.ts` на запросы к БД. Адаптер Supabase в коде пока не написан.

## Деплой на Vercel

1. Загрузите репозиторий на GitHub.
2. В Vercel: New Project → выберите репозиторий (Framework: Next.js, команды по умолчанию).
3. Переменные окружения для демо не нужны.
4. Для production сначала выполните раздел «База данных».

## Первый администратор

Кабинета админа и реальной авторизации пока нет. После подключения Supabase Auth: зарегистрируйте пользователя и вручную выставьте `role = 'admin'` в таблице `user_profile`.


## Версия 3: что добавлено (НЕ проверено сборкой)

В среде разработки не было сети, поэтому `npm install`, `tsc --noEmit`, `next build` и сценарии Playwright для этой версии **не запускались**. Код написан по паттерну Global; перед использованием выполните `npm install`, `npx tsc --noEmit`, `npx next build` и пройдите сценарии вручную.

- **Group Orders** (`/group`): группа создаётся или находится по совпадению препарата, дозировки и формы (нормализация регистра, пробелов, запятой). Поставщик видит только общий объём и присылает предложение на объём, импортёр одобряет или отклоняет (отказ только с причиной), каждый участник подтверждает отдельно, импортёр может продлить набор на 7 дней или закрыть группу. Файлы: `src/lib/group-actions.ts`, `src/components/GroupForms.tsx`, `src/app/group/page.tsx`.
- **Cargo** (`/cargo`): заказ даже на 1 упаковку, класс хранения (комнатная, холод, заморозка), проверка импортёром, включение в отправку только заказов одного класса (проверяется на сервере), расчёт стоимости по демо-тарифу, статусы заказа и отправки, распределение по точкам выдачи, альтернативная точка только с согласия покупателя. Файлы: `src/lib/cargo-actions.ts`, `src/components/CargoForms.tsx`, `src/app/cargo/page.tsx`.
- **Администратор** (`/admin`): агрегированная статистика без персональных данных, список аптек, каталога и демо-пользователей, сброс демо-данных.
- Кабинеты поставщика и импортёра расширены разделами Group Orders и Cargo.
- Статусы Cargo и тарифы выбраны разработчиком: исходное ТЗ не было приложено к этому чату, сверьте названия статусов с ТЗ.


## Каталог в Supabase и картинки препаратов (не проверено сборкой)

Каталог можно хранить в Supabase и редактировать в кабинете администратора (`/admin`): добавлять, менять и удалять препараты, загружать картинку упаковки (JPG, PNG, WebP до 3 МБ). Остальные данные (заказы, заявки, группы, отправки) пока в SQLite, на Vercel они временные.

1. Создайте проект на supabase.com.
2. SQL Editor, New query: вставьте `supabase/migrations/0003_catalog.sql`, Run. Создаётся таблица `catalog_medicine` и публичный бакет `medicine-images`. Миграции `0001` и `0002` для этого НЕ нужны.
3. Settings, API: скопируйте Project URL и `service_role` key.
4. Локально создайте файл `.env.local` (он не попадёт в git) по образцу `.env.example`. На Vercel: Settings, Environment Variables, добавьте обе переменные и сделайте Redeploy.
5. Войдите администратором, откройте `/admin`. При первом заходе тестовые препараты загрузятся в базу автоматически.
6. Цену и остаток по новому препарату задаёт аптека в разделе «Остатки и цены».

Ключ `service_role` даёт полный доступ к базе: используется только на сервере и не должен попадать в код, репозиторий или браузер. Если он где-то засветился, перевыпустите его в Supabase.
