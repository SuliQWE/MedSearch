# Промт для продолжения MediFinder (версия 3)

Ты Senior Full-Stack Developer. Продолжи MediFinder (Next.js 14 + TypeScript + Tailwind + Lucide, интерфейс на русском, сом). Приложи ZIP v3 и исходное ТЗ. Не переписывай рабочее.

## Первым делом (в v3 это НЕ делалось: не было сети)
1. `npm install`, `npx tsc --noEmit`, `npx next build`. Исправь ошибки в новых файлах: `src/lib/group-actions.ts`, `cargo-actions.ts`, `admin-actions.ts`, `src/components/GroupForms.tsx`, `CargoForms.tsx`, `Badges.tsx`, `Msg.tsx`, `AdminReset.tsx`, `src/app/{group,cargo,admin}/page.tsx`, правки в `store.ts`, `importer/page.tsx`, `supplier/page.tsx`, `Header.tsx`.
2. Перед тестом удали `./data` и перезапусти dev-сервер. Прогони Playwright-сценарии: Group (два покупателя в одну группу, предложение, одобрение, раздельное подтверждение, закрытие при нехватке объёма), Cargo (заказ, проверка, отправка с разными классами хранения должна отказать, альтернативная точка, распределение, выдача), доступ по ролям, сброс демо-данных админом.
3. Сверь статусы Cargo и логистические группы с ТЗ (в v3 выбраны разработчиком), демо-тарифы помечены как демо.

## Остаётся из плана
- **Supabase:** применить `0001`, `0002` на тестовом проекте, проверить RLS реальными пользователями; Auth вместо cookie-входа; переписать `store.ts` и все `*-actions.ts` (таблицы для groups, cargo_line, shipment вместо JSON в `kv`); audit_log; первый администратор скриптом; cron `expire_reservations()`.
- **Кабинеты:** админ: редактирование каталога, аптек, пользователей из интерфейса; расширить поставщика и импортёра; карта вместо схемы.
- **Финал:** мобильная и планшетная проверка, состояния загрузки и ошибок, защита от двойной отправки, `.env.example`, инструкция деплоя на Vercel. Помни: SQLite не работает на Vercel.

## Правила
Только Lucide, без эмодзи; все демо-данные помечены; не выдумывать аптеки, лицензии, отзывы; MediFinder — посредник, не обещает ввоз до проверки импортёром и не обходит рецептурные требования; не заявлять готовность непроверенного.
